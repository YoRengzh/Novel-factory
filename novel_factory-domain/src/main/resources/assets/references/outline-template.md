# 大纲规划模板

长篇与中短篇的大纲粒度怎么选：先判断作品长度级别，再决定是否需要分层滚动展开；含各级检查清单。
本文件只讲规划思路与字段口径，**不含任何可供照抄的 JSON 结构**（字段以运行时注入的 schema 为准）。

## 第一步：先判断作品长度级别

### 短篇 / 单卷故事

- 适用：单冲突、单目标、角色少、结局集中
- 参考长度：8-25 章
- 建议粒度：扁平卷纲（单卷，弧少）

### 中篇 / 多阶段故事

- 适用：有阶段升级、数条支线、人物关系会变化
- 参考长度：25-60 章
- 建议粒度：扁平卷纲，或轻量分层（卷 + 首弧展开）

### 长篇连载 / 网文型故事

- 适用：题材天然具备持续升级空间、长期关系张力、多个阶段目标、可扩展世界、长期谜团或长期成长线
- 参考长度：80-200+ 章
- 建议粒度：分层滚动（前 2 卷给弧骨架，其余卷先留骨架，只把第一弧的章节展开）

> 注：以上是**规划粒度**的建议，不是输入字段名。输入侧的正文大纲走 `outline` 与 `chapterGoal`
> 两个文本字段（见 `StoryContextEntity`），分层的卷/弧/阶段结构由系统在生成过程中滚动产出。

## 第二步：判断是否必须使用分层滚动

只要满足下面任意 2 条，就优先按分层滚动来做：

- 世界观需要逐步展开，而不是一次性讲完
- 主角成长不是一次跃迁，而是多阶段升级
- 人物关系会在多个阶段持续变化
- 中期和后期存在不同类型的主矛盾
- 需要多次地图/势力/身份/目标切换
- 题材明显更像连载型商业小说，而不是单卷故事

## 第三步：长篇时不要直接做“全书章节流水账”

长篇规划顺序建议是：

1. 作品卖点与差异化
2. 长期故事引擎
3. 卷级主题与升级
4. 弧级目标与阶段转折
5. 章节级事件与钩子

错误做法：

- 先写 20 章梗概，再强行拉长
- 每卷都重复“遇敌-变强-换地图”
- 只有主线升级，没有关系升级
- 前期把所有大秘密透支完，中后期只能重复套路

## 大纲的分层与字段口径

本项目的运行时大纲**分四层滚动展开**，不需要（也不应该）一次写完整本书的章节流水账：

- **卷级** `VolumeBlueprintEntity`：卷号 / 卷标题 / 卷主题 / 起止章节 / 弧清单 / 卷出口条件
- **弧级** `VolumeBlueprintEntity.ArcPlan`：弧编号 / 一句话目标 / **预计章数**（`estimatedChapters`，
  各弧之和应约等于卷章数）/ **转折点**（`turningPoint`，一句话）。规划阶段窗口时须与弧预算对齐。
  弧的起止章节与完成状态仍不是结构化字段——起止由该弧下各阶段蓝图的章号区间承载。
- **阶段级** `StageBlueprintEntity`：阶段目标 + **可机械核验的退出条件**（阶段末章后逐条核验，
  未达成会原样注入下一版重验一次，仍不达成则强制出账），阶段边界生成一版并链式结转。
- **章节级**：章节计划一次只规划**一个段**（惰性分段规划），每章含
  标题 / 目标 / 出场角色 / 关键事件 / 结尾悬念 / 章型。

推进到骨架弧或骨架卷时，由**卷蓝图节点与阶段蓝图节点**按批滚动展开。
本系统**没有**独立的 "Architect" 角色、服务或编排入口——不要假设存在这样一个组件。

### 字段以运行时为准，本文件不提供可照抄的 JSON

各层的 JSON 字段由代码在装配 prompt 时注入：章节计划见 `BuildChapterPlanPromptNode` 中的
schema 指令块（其中含当前可解析字段的示例）。

**本文件刻意不复制任何可照抄的模板**——一旦这里的示例与运行时代码脱节，模型就会照抄错的
字段名（把 `keyEvents` 写成 `core_event`、把 `chapterNo` 写成 `index`、把 `endingHook` 写成 `hook`），
导致结构化输出解析失败并触发重试。要确认字段口径，请看两处**权威来源**：

- 代码：注入 schema 的那一处（如 `BuildChapterPlanPromptNode` 的 schema 指令块）
- 落盘产物：`memory/rolling-outline.json`（卷/阶段）、`memory/summaries.json`（章节摘要）、
  `generation-records/*/chapter-plan.yml`（章节计划）

上面「作品长度级别 / 是否必须分层 / 规划顺序 / 各级检查清单」四节描述的是**规划思路**，
不含任何需要照抄的结构，可以放心参考。

## 长篇卷级检查清单

按本书卷级任务检查相关问题；不是要求每卷同时新增信息、升级矛盾、得失并举和关系质变，适用项可以保持稳定或明确不适用：

- 这一卷需要交代或确认哪些世界信息？
- 核心矛盾是推进、缓和、维持还是收束，原因是什么？
- 主角实际得到了什么、失去了什么，或为何保持原状？
- 主要关系发生了哪些变化，哪些关系保持稳定？
- 卷末是否还需进入下一卷，继续或结束的依据是什么？

## 长篇弧级检查清单

按本书实际弧目标检查；日常、观察或关系弧可以不采用对抗—转折结构：

- 这条弧需要交付什么目标、体验或人物理解？
- 确有阻力时，来自谁、什么规则或什么代价？
- 是否需要转折，其发生或不发生的理由是什么？
- 弧末哪些状态变化、保持稳定或留下余韵？

## 章节级检查清单

- 检查本章与当前弧或作者任务的关系；日常、独处、观察与静场也可独立成立
- 事件、关系、认知或氛围是否交代充分，不要求每章一个不可删除事件或新增暗线
- 结尾可落在结果、决定、关系、余韵或悬念，不强制新钩；需要悬念时避免同一种揭秘密模板
- 前期介绍世界的篇幅按读者理解与本书任务安排，不强制每章同步推进人物和冲突
