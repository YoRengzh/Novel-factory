# 章节规划交付（规划层专用）

> 本文件只用于章节计划。结构、范围及明确剧情承诺是交付契约；人物数量、内心比例和事件条数按本章任务安排。
> 以作者大纲、创作要点、题材设定和当前章节任务为准，不通过凑对白、拆碎事件或提前收束来填满章数。

## 规划要求

1. 规划授权范围内的全部章节，编号连续，字段和枚举符合 schema；不生成正文。
2. 每章给出具体目标、关键事件及结果。调查发现、独处思考、持续行动、关系消化或协作均可承担章节任务；不强制每章出现新的对手、争执或不可逆损失。
3. 事件数量由实际因果与本章容量决定。同一场审讯或一段连续行动可以成章，不为了数量拆成重复的小事件。
4. 章末给出具体的结尾落点，可以是动作、决定、阶段性结果、关系变化、余韵或悬念；收官允许闭合，不必制造下一章危机。
5. 篇幅服从本次明确交付配置。不要把统计均值当作章节内容需求；篇幅不足时检查计划是否充分，不默认通过增加对白补量。

## 对话声明

- 交流由场景的意图、阻力和结果承载。审讯、交涉和协作写清双方的诉求与影响，为正文展开有效对白留足空间。独处或静场按实际任务安排。
- 不单独生成兼容字段 dialogueScenes。
- 计划不写可被正文逐字照抄的台词原话；纸条、回执等书面物件的文字不因此删除。
- 对白句长、轮次与直接程度服从人物声音。句数目标由正文执行。

## 事实与来源

- 角色能做什么、知道什么，以及时间、地点、物品、伤势等状态，必须承接已建立的设定和事件。
- 阶段方向不等于每章任务清单。不要为了兑现所有里程碑提前透支后段剧情。
- 伏笔登记放入 foreshadowNotes，事件只描述正在发生的事；没有登记需求时留空。未能安排的明确承诺应说明冲突，不用无关剧情凑回收数量。
- timeAdvance 仅在确实跨时间时填写，不把时间推进作为每章的交付任务。

自检：计划是否给出了当前章节真正要发生的事，而不是把写法配额换成了剧情安排？
