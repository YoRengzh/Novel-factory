# StartDrafts

> **命名说明**：源码项目名为 `novel_factory`（仓库、Maven 模块与 jar 均沿用此名），对外发布的桌面安装包更名为 **StartDrafts**——两者指同一套代码，下文出现的两个名字不做区分。

**面向长篇小说与网文连载的无人值守生成产线。** 从设定集、卷蓝图、阶段蓝图到逐章正文、审校、修订、定稿，整批跑完并留下可复核的体检报告；你只在调参和裁决时出现。

> 实现形态是**多智能体协作 + 确定性编排**：规划、写手、审校、评审、裁决、摘要各由一个角色承担，可分别路由到不同模型甚至不同模型族——候选盲评刻意让写手与评审分属两族，专门对抗"自己评自己"的自偏好；而它们之间的先后与分支由显式管线节点链决定，不靠模型自行协商。
>
> 两种用法：**写作者**直接用 [StartDrafts 桌面版](https://github.com/YoRengzh/Novel-factory/releases/latest)（Windows 双击即用）；**开发者**读源码，把它当作长篇生成管线的工程参考实现。


**技术栈**：Java 17 · Spring Boot 3.4.3 · Spring AI 1.0（OpenAI Chat Completions / Anthropic Messages / OpenAI Responses 三协议）· Maven 多模块 · 内置向量库（Qdrant 可选）· Electron 桌面壳 · 原生前端
**规模**：6 个 Maven 模块 · 主代码 4.4 万行 / 测试 3.2 万行 · 134 个测试类 1,562 个用例

## 它能做什么

按写一本长篇的顺序组织：设定 → 卷蓝图 → 阶段蓝图 → 逐章正文 → 审校修订 → 体检报告。每一步的结果都落成可 diff 的文件，下一步接着用。

### 设定集：一句话起步

给一个题材关键词，AI 产出书名、风格、世界观、视角、目标人群、基调、主人公、故事大纲、章节目标与建议总章数，回填到表单后逐项可改。不满意可以只重生成某一个字段，也可以只重生成大纲（其余字段锁定不变）。

### 卷蓝图与阶段蓝图：全书长期锚 + 滚动大纲

卷蓝图定全书方向（一卷 = 一次剧情移动）；阶段蓝图在其窗口内滚动生成，每跨阶段边界出一版。蓝图含悬念档位表（3–6 档有序枚举）与逐章主线推进，两者分别管"走到第几格"和"这一章做了什么"。

蓝图带**反套路检查**：比对近 10 章实际摘要与本次章级推进，检出明确复述与"问题→能力解围→旁人认可"的重复循环，走一次带反馈返修。这是关键词启发式，不阻断生成，只在告警里留痕。

### 逐章正文：质量门禁在写的时候就开着

每章生成后自动跑审校（禁泄逐字扫描、一致性核对、AI 腔检测）、段落密度审校、必要时定向补丁修订。低置信章节触发候选盲评：异模型整章重写 + 机械门禁 + 异族评审二选一。

### 段落级编辑：选中一段，只改这一段

正文阅读时选中一段文字，浮动工具条给出三个动作：

- **润色**：只改表达（去空话、把抽象评价换成可观察细节、长短句交替），不改事实与篇幅；
- **扩写**：在原有事实基础上补细节，目标 1.5–3 倍篇幅，禁止靠形容词堆砌撑长度；
- **续写**：沿原文语气与事件往下写一小段，承接上文动作，不提前解决矛盾、不引入无关新人物。

结果以**左右对照**呈现（原文 / 改写后），你确认后才替换，再走常规保存（触发摘要回流）。轻量诉求不付整章修订的成本：单次短 prompt 调用，输出上限压到 2048 tokens。

### 批末体检：可归因的质量基线

每批（默认 5 章）结束输出 30 项量化指标，每项带历史基线与可执行建议。这是判断"这批比上批是好是坏"的唯一依据——不是"生成完就结束"。

### 模型接入：中转站 + 三协议

设置页登记多个中转站（OpenAI 兼容 / Anthropic / OpenAI Responses），一键拉取模型列表；全局、每个场景、兜底模型都可以只选"哪个站的哪个模型"，不必手填地址密钥。跨协议供应商（如评审指向 Anthropic 站）会自动切换客户端。

### 资料与文风：可增补的写作资产

内置 58 篇写作资料 + 4 篇文风。在「04 资料设置」里可以导入自己的范例/题材资料（进同一套索引与向量检索），或按题材覆盖文风——无需改代码重新打包。


## 它解决什么问题

长篇连载（50 万字以上）靠单次提示无法保证质量，真正的难题是**跨章的工程约束**。本项目把每类约束做成机制：

| 长篇难题 | 对应机制 |
|---|---|
| 写到后面人物状态、持有物、时间线自相矛盾 | 三账本（角色/物品/势力）+ 一致性索引 + 时序锚（境界式锁定） |
| 账本/摘要"记录了正文里没有的事" | **证据链机械校验**（8 档匹配）——模型必须给出正文原文引证，匹配不上就不入账 |
| 伏笔"埋了就忘"或"埋了立刻收" | 伏笔排期表（PLANNED→PLANTED→PAID/MISSED 状态机）+ 卷末清账裁决 + 动态权重（积压到阈值必须评估）+ 写手视图去元信息 |
| 写手"提前说漏嘴"谜底 | 禁泄清单：对谜底关键词在正文里**逐字扫描**，命中即 BLOCKING（不做语义判断，宁漏勿误报） |
| 模型自我修正的同质化陷阱 | 候选盲评：低置信章触发异模型整章重写 + 机械门禁 + 异族评审 |
| 反复用同一批套话与同一套情节 | 疲劳词表（内置 60+ 中文套话，可外部覆盖）+ 已用情节模式黑名单（舞台复用/同型冲突方/能力展示章数） |
| 计划写了、正文没写 | 计划遵循度：正文与计划事件的**最长公共子串**覆盖率，低于 0.6 即触发加审 |
| 时间/年龄漂移 | 时序锚 v2：计划声明的 timeAdvance 是唯一合法推进通道，审计回验 |
| "这批比上批是好是坏"无法归因 | 批末体检：30 项量化指标，每项带历史基线与可执行建议 |
| 长跑批中途失败、无人值守烧钱 | 逐章检查点/回滚 + 人工审批挂起 + token 预算熔断（命中后**当前章写完即停**，不留半截） |

## 几个不常规的设计取舍

这些是本项目与"多套几层提示词"最不一样的地方，也是它在长跑中不容易崩的原因：

**1. 能机械校验的，绝不交给 LLM 判断。**
摘要和账本最容易编造"正文里没有的事实"，所以每条状态都必须附 ≤50 字正文引证，再用 8 档匹配（精确→归一化→分段→短语覆盖→锚定→跨度）判定引证是否真实存在——"放宽的是表述，不是事实有无"。禁泄是逐字 `indexOf` 扫描，计划覆盖率是 LCS，重复用语是词表统计。**判断标准始终是可复算，而不是"模型觉得像"。**

**2. 失败语义刻意不对称——该硬失败的地方不许静默降级。**
向量资料检索失败会**直接终止作业**（注释写明：静默降级会让作业在低质量注入下跑完）；而 LLM 选择资料失败则静默返回空、不阻塞。模型降级链里唯一不换模型的是 `CONTENT_POLICY`（内容审计与换哪个模型无关）。预算熔断、检查点、自动续批则全部 fail-soft，不反噬主流程。哪里该硬、哪里该软，是逐处设计过的。

**3. 状态机与生命周期，而不是散落的标志位。**
写作模式按契约完整度自动判定（FREE / SCAFFOLDED / RECOVERY，缺计划就收紧而非自由发挥）；伏笔走四态；质量债用"连续 2 章无同维度复发"验证式核销，**没有验证信号的债永不核销**（不伪造结论）；全书完结上限是 sticky 的——只能下调不能抬高。

**4. 状态尽量做成纯函数，可确定性重算。**
伏笔权重 `score = 重要性×10 + 滞留章数×5`，续批决策 `decide(...)` 同样是纯函数——零新增存储，任何时刻都能从摘要重算，不存在"状态漂移需要修数据"。

**5. 提示词预算是"块优先级淘汰"，而不是一刀切截断。**
前缀由 8+ 个块拼成（末态红线/记忆/风格/一致性/禁泄/情节黑名单…），每块有独立封顶，但**封顶之和会击穿窗口**。所以装配层有总额预算，超预算时按块优先级淘汰，且**渲染顺序与淘汰次序分离**——丢谁和排谁在前是两件事。禁泄块标记为不可截断（截断会静默丢词），放不下就整块弃并**在日志点名**"依赖下游兜底"。预算日志强制自洽，可脚本对账。

**6. 错误分类驱动重试与降级，而不是无脑重试。**
供应商报错被分为 7 类，每类带两个正交布尔——"同模型重试是否有意义"和"换模型是否有意义"。`UPSTREAM_INTERNAL`（500/engine abort）被特别归为"换模型比原样重试更有效"——这条来自实测：某个模型跑 795 秒后被上游 abort。降级链**硬上限 3 个**，防止一条长链一次失败烧掉整串费用。

**7. 有校准设施，而不是只能靠感觉调参。**
审校判据留了 A/B 变体开关（默认 A 与生产逐字节一致）；"修订耗尽仍未解决的 BLOCKING"整包回流成离线校准集；另有一套需显式开关的评测框架（跨系统盲评、审校校准、运行时采样），共 6 个类 1428 行。

## 和"逐章循环"式生成的区别

市面上多数小说生成工具是同一个形态：一句话设定 → 逐章循环生成 → 输出全文，跨章状态靠"把前文塞进上下文"。这个形态有三条假设，会随篇幅增长逐条失效：

1. **上下文装得下**——长到一定程度必须截断，截断即遗忘，且遗忘是静默的；
2. **模型自评能代替机械校验**——同一模型既写又评会偏向自己的措辞和结构，越改越同质；
3. **"生成完"就是终点**——没有可归因的质量基线，所以"这批比上批是好是坏"永远说不清，调参只能靠感觉。

本项目的取舍是：能机械校验的一律不进提示词；账本、伏笔、时间线全部落成可 diff 的文件；每批产出体检报告，让"变好还是变坏"可归因。**判断标准不是"能不能生成"，而是"能不能定位到是哪一层机制没生效"**。

## 快速开始

### 桌面版（Windows）

1. 从 [Releases](https://github.com/YoRengzh/Novel-factory/releases/latest) 下载 `StartDrafts.Setup.exe` 并安装；
2. 启动 StartDrafts，进入「05 设置」配置模型接入：可直接填 Base URL 与 Key，也可在下方「中转站管理」登记多个 OpenAI 兼容 / Anthropic 中转站，一键拉取模型列表后用下拉选用（建议同时填 embedding Key，开启向量增强）；
3. （可选）进入「04 资料设置」补充你自己的写作范例与题材资料、或改写各题材文风——与内置资料同等待遇，进向量索引按需注入；
4. 回到「01 生成」创建故事、提交生成；每批结束后看**批末体检报告**。

### 源码运行

四步：**打包 → 启动 → 配置模型 → 打开工作台**。完整版（含截图与排错）见[快速开始](docs/quickstart.md)。

```bash
# 1) API Key 模式可先配置密钥（ChatGPT 登录模式跳过这步）：
export LLM_API_KEY=sk-你的密钥
#   或复制 config/application-local.example.yml 到
#   novel_factory-app/src/main/resources/application-local.yml 后填入
#   （该文件名已被 .gitignore 排除；文件里的值会覆盖环境变量，所以只启用你要改的项）

# 2) 打包（首次约 20 秒，不需要预先安装任何模块）
mvn -pl novel_factory-app -am clean package -DskipTests

# 3) 启动
java -jar novel_factory-app/target/novel_factory-app.jar

# 4) 打开工作台
#    http://localhost:8080
#    设置 → 认证方式：可选择 API Key，或 Continue with ChatGPT 完成浏览器授权
```

> 开发时想反复重启，用 `mvn install -DskipTests` 装齐 6 个模块一次，之后 `mvn -pl novel_factory-app spring-boot:run` 即可（改代码不用重打包）。
> 完整测试套件：`mvn test`（1,562 个用例，1~2 分钟）。

每批（界面默认 5 章）结束后看**批末体检报告**——30 项指标 + 可执行建议，这就是本系统的仪表盘。

## 批末体检长什么样

共 30 项指标，每项三列：**当前值 ｜ 目标（含历史基线）｜ 明细**，级别 OK / WATCH / DEGRADED / CRITICAL，尾部附建议。真实示例（节选）：

```text
OK      账本完整度       94.06%（目标 ≥90%） ｜ 严格 523 / 放宽 47 / 挂起 11
OK      对白轮次密度     22.50次/千字（目标 ≥9）
WATCH   候选选优触发率    52%（目标 ≤30%） ｜ 触发 39 / 65 章
DEGRADED 进度对齐        7段（目标 ≤1 段） ｜ 第 65 章按大纲应处【61-70章 2009年/11岁】段
建议：进度滞后约 6 年：……两条出路：①规划层加速（跳月/压缩日常）；
②承认慢节奏，重排大纲章段预算。不应长期维持现状——路标与正文漂移会越滚越大。
```

每条 DEGRADED 都对应一个可执行的下一步——这是本系统与"生成完就结束"的工具最大的区别。

## 架构

六个 Maven 模块，依赖单向：`types`（枚举/值对象）与 `api`（DTO）不依赖任何内部模块；`domain` 只依赖这两个，承载全部机制（管线节点、质量策略、记忆层、提示词装配）；`infrastructure`（文件仓库 / 内置向量库·Qdrant / LLM·Embedding 网关）与 `trigger`（HTTP 端点）并列依赖 `domain`；`app` 装配二者并启动。

- **存储**：文件仓库——`docs/workspace/stories/` 下 JSON（正文、摘要、三账本、蓝图、检查点），全部可 git、可 diff、可手工修。写入走"临时文件 + 原子替换"并按故事加锁；记忆类文件损坏即硬失败（静默读空等于丢账本），观测类文件损坏仅告警。
- **向量库**：默认**内置向量库**——向量以自定义二进制格式（NVTB）随故事目录落盘，暴力精确检索（本规模下毫秒级，优于近似索引的精确性），删除故事即全清。进阶可切回 Qdrant（`story.vector-store.mode: qdrant`）。
- **前端**：原生 HTML/CSS/JS（无构建步骤），随 jar 由后端同源提供；Windows 桌面版用 Electron 壳包成单安装包（内嵌 jpackage 的 Java sidecar，单实例锁、端口探测、退出时清理进程树）。
- **可换的模型**：场景级路由——17 个场景（章节计划/正文/审校/评审……）可独立配模型、温度、思考开关，也可按场景配不同的 base-url 与 api-key，用于让评审场景指向异族模型以保证盲评中立。
- **多供应商与协议**：设置页可登记多个中转站（OpenAI 兼容 / Anthropic / OpenAI Responses），一键拉取模型列表后以「站名·模型」标注在场景矩阵里选用；地址带不带 `/v1` 均可。
- **可增补的资料层**：内置 58 篇写作资料 + 4 篇文风，用户可在「04 资料设置」里导入自己的范例/题材资料（进同一套索引与向量检索），或按题材覆盖文风——无需改代码重新打包。

详细设计（管线节点链、20 项机制的逐一说明、存储目录契约）：[架构与机制](docs/architecture.md)

## 支持的模型与服务

软件不提供模型，也不代管额度。你在设置里填自己的地址、模型名和 API Key。支持三种协议：

- **OpenAI Chat Completions**：绝大多数中转站与兼容供应商；
- **Anthropic Messages**：Claude 官方与 Anthropic 协议中转站（`x-api-key` 鉴权）；
- **OpenAI Responses**：官方 Responses API 与兼容中转站（gpt-5 系等）。

设置页内置中转站登记表，可添加多个站并各自选协议；「获取模型」一键拉取该站模型列表，之后全局/场景/兜底的模型输入框都是可点选的下拉。

| 服务商 | 协议 | Base URL 示例 |
|---|---|---|
| DashScope（阿里） | OpenAI 兼容 | `https://dashscope.aliyuncs.com/compatible-mode` |
| DeepSeek | OpenAI 兼容 | `https://api.deepseek.com` |
| 硅基流动 | OpenAI 兼容 | `https://api.siliconflow.cn/v1` |
| 智谱 BigModel | OpenAI 兼容 | `https://open.bigmodel.cn/api/paas/v4` |
| OpenAI | OpenAI 兼容 / Responses | `https://api.openai.com` |
| Anthropic | Anthropic Messages | `https://api.anthropic.com` |
| one-api / new-api 等自建中转 | OpenAI 兼容 | 你自己的地址 |
| Ollama（本地） | OpenAI 兼容 | `http://127.0.0.1:11434/v1` |

地址带不带 `/v1` 都可以：程序会自适应路径，避免拼出 `/v1/v1/chat/completions`。

向量检索另需一个 embedding 模型（设置页「向量检索分区」），与聊天模型可分开配。

## 常见问题

**免费吗？**
代码以 Apache-2.0 开源，软件本身不收费。调用云端模型的费用由你和模型服务商结算；用本地 Ollama 则无需付费。

**需要什么模型？**
任何兼容上述三种协议的模型都可以接。生成质量取决于你选的模型——本项目对跨章一致性有机械约束，但不对模型输出质量作保证。作者实测的较优组合见下方「模型实测」。

**能写多长？**
总章数由你设定，没有固定上限。写每一章时 AI 拿到的是本章计划、相关记忆摘要、前文摘要与必要的资料片段，而不是整本书的聊天记录——所以篇幅不受单次上下文窗口限制。

**能改提示词吗？**
可以改资料与文风（04 资料设置，导入自备资料或覆盖文风）。核心规则文件打包在 jar 内，改它需要改源码重新打包——这是有意为之：规则文件的标题锚点是程序切片接口，随意改动会让作业直接终止。

**数据存在哪？**
`%APPDATA%\StartDrafts`：`docs/workspace/stories/` 下是正文、摘要、三账本、蓝图、检查点（纯 JSON/文本，可 git、可手工修）；`data/` 下是运行时覆盖配置与日志。全部在本机，只有发起生成时相关提示词才会发给你配置的模型服务。

## 已知限制

- 面向**中文长篇**设计（分词、账本、体裁模板均以中文假设为前提）；
- 桌面安装包目前仅 **Windows**；macOS / Linux 请走源码方式；
- 单机文件存储：多机协作、多人共写不在当前范围内；
- 每章生成成本 8-25 万 token（视质量档位）——这是"全链路审校+候选"的定价，预算敏感请调低候选触发；
- 大纲（chapterGoal）需要作者按"章段+时间标记"格式编写；
- 候选盲评与异族评审走独立模型配置（`scene-models.chapter-rewrite` 与 `chapter-judge`）。只有单一模型族可用时，把 `candidate.enabled` 置为 `false`——保持默认的 `true` 会在评审阶段空转失败；
- 向量增强需要 **embedding API Key**（内置的是"存向量"，"变向量"仍需 embedding 模型；未配置时以无增强模式降级，日志单条提示）；若动态资料检索选用 vector 模式但检索失败，会快速终止而非静默降级——可切回 LLM 索引选择模式；
- 启动耗时：解包布局下后端就绪约 4-5 秒（桌面版已加启动闪屏，点图标即时出画面）；
- **段落级编辑只在阅读态生效**：编辑态（contenteditable）下不弹浮动条，避免挡住输入；选中片段限 8–2000 字，超长请用整章修订；
- 段落级编辑走关键词约束的短 prompt，不做账本校验——它改的是表达，不是事实。若要动情节，仍应走整章修订或直接手改；
- **ChatGPT 套餐授权（实验性）**：依赖 OpenAI 未公开文档的第一方授权通道（参数取自开源的 Codex CLI），不保证长期可用；该授权也不含 Embedding，向量检索仍需独立 API Key；
- 本协议只覆盖**代码**：生成小说内容的版权归属由「谁运行 + 所用模型服务商的条款」决定，本仓库不做任何主张——商用或公开发布前，请自行确认所用模型方的输出使用权与发布平台规则。
